# まなびのコード — P1開発プレビュー

承認済みの基本設計書第6版・詳細設計書第4版を基準に、個人学習の最初の縦断フローを実装したものです。**正式運用版ではありません。既存サーバーへの配置・公開はしていません。**

## 起動

動作確認環境：Windows 11、Python 3.14.3、Node.js 24.15.0。依存パッケージはプロジェクト内に保存します。

初回セットアップ（プロジェクトのディレクトリーで実行）：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r backend/requirements-lock.txt
cd frontend
npm.cmd ci
```

ターミナル1：

```powershell
cd backend
../.venv/Scripts/python.exe run.py
```

ターミナル2：

```powershell
cd frontend
npm.cmd run dev
```

ブラウザーで <http://127.0.0.1:5173/> を開きます。終了はそれぞれのターミナルで `Ctrl+C`。共有PCや公開サーバーでは起動しないでください。

## 今回できること

- 個人利用を既定とし、教室の登録・講師・共有フォルダーを使わずに学習を開始。
- Java／Python／基本情報の独立した入門コースから1つを選択。各1単元・2問。教材は自作で、公式試験問題ではありません。
- 教材を読む→選択式確認問題に回答→サーバー採点・解説→復習→修了確認→進捗表示。
- ブラウザーで32バイトのランダムな学習キーを生成し、IndexedDBへ保存・読み戻し確認。次回は自動再開。
- 任意のLS1コード表示・書き出し・復旧。URLにキーを入れず、外部QRサービスも使用しません。
- 学習のない記録の30日期限と、初回回答による期限状態の変更。GETでは期限を延長しません。
- 同一リクエストの再送を24時間冪等化。SQLiteの書き込みトランザクションで回答連番を保護。

## 個人情報とローカルデータ

氏名、メール、GitHubアカウント、リポジトリーURL、ソースコード、自由記述の保存欄はありません。学習キーの平文はサーバーDBに保存せず、別ファイルのpepperを使ったHMACで照合します。IP、User-Agent、Referer、認可ヘッダーはDBに保存しません。APIの入力は許可フィールドだけを受理し、エラー応答に入力・例外詳細を含めません。`run.py` はアクセスログと例外ログを無効にします。

サーバー側の開発データは `backend/.local/learning.db`、pepperは `backend/.local/pepper.bin`。このディレクトリーは配布ZIP・Git管理から除外します。ブラウザーに保存するのは学習キー・初回再送用ID・選択コース・バックアップ操作状態で、進捗の本体はAPI側に保存します。キーの紛失時に本人確認による復旧はできません。

プレビューの開発サーバー全体について、公開環境での「識別情報がどこにも保存されない」検証は未完了です。リバースプロキシ、OS、障害ダンプ、DB、バックアップまで含む正式運用の確認が必要です。

## 設計に対する実装段階

|領域|現在|次の実装|
|---|---|---|
|UI / API|React・TypeScript / FastAPI、下記11エンドポイント|残りのcore APIと正式レスポンス契約検証|
|DB|ローカル試作専用SQLite、3表|承認済み28表のPostgreSQLスキーマ・マイグレーション・ロック／一意制約試験|
|教材|版ID固定のコード内サンプル、単一選択問題のみ|DB管理、複数選択／並べ替え、必須目標別の進捗と復習、5段階の実践教材|
|資格|FEアルゴリズム入門1単元|シラバス版と範囲対応、科目別分析、Java Silver／Python資格|
|個人学習|1記録につき1コース、1単元を自動再開|複数コース、途中位置・好み変更、実践記録／自己確認|
|キー|生成・自動保存・任意LS1書き出し／復旧|キー更新・失効、レコード削除、暗号化復旧ファイル|
|保存期間|空記録の期限判定／回答による昇格|日次削除、24か月保持、削除台帳とバックアップからの再削除|
|運用|127.0.0.1限定、development以外は起動拒否|Ubuntuコンテナー、TLS、レート制限、監視、障害時の安全な診断、復旧試験|
|教室 / GitHub|いずれも未実装・無効|個人利用の受入完了後、教室は任意拡張。GitHub参照はブラウザー内限定|

SQLiteの表構造と完了フラグは**破棄可能な試作モデル**です。正式DBへの移行互換性はありません。本番用Composeは、28表の実装と運用試験に合わせて用意します。教材全体やP1受入条件のすべてが完了した状態ではありません。

## 実装API

すべて `/api/v1` 配下。書き込みにはUUID形式の `Idempotency-Key` が必要です。

```text
GET  /health
GET  /catalog
GET  /units/{unit_id}/material
POST /records
GET  /records/me
GET  /learning-home
GET  /questions/{question_id}
POST /questions/{question_id}/attempts
POST /units/{unit_id}/review-next
POST /units/{unit_id}/assess
GET  /progress
```

正式仕様との差：教材・問題は固定サンプル、目標別進捗は空配列、教材修了は各問題への正答を必須とする試作用判定です。期限後の実データ削除、キー更新・失効、削除台帳は未実装です。
