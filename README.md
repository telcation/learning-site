# まなびのコード — P1開発プレビュー

承認済みの基本設計書第6版・詳細設計書第4版を基準に、個人学習の最初の縦断フローを実装したものです。**正式運用版ではありません。既存サーバーへの配置・公開はしていません。**

## 起動

動作確認環境：Windows 11、Python 3.14.3、Node.js 24.15.0。依存パッケージはプロジェクト内に保存します。

初回セットアップ（プロジェクトのディレクトリーで実行）：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r backend/requirements-lock.txt
cd frontend
npm.cmd ci
```

ターミナル1：

```powershell
cd backend
../.venv/Scripts/python.exe run.py
```

ターミナル2：

```powershell
cd frontend
npm.cmd run dev
```

ブラウザーで <http://127.0.0.1:5173/> を開きます。終了はそれぞれのターミナルで `Ctrl+C`。公開サーバーでは起動しないでください。一時端末モードも開発プレビューであり、教室への実導入前に専用ブラウザープロファイルでの実機受入確認が必要です。

## 今回できること

- 個人利用を既定とし、教室の登録・講師・共有フォルダーを使わずに学習を開始。
- Java／Python／基本情報の独立した入門コースから1つを選択。各1単元。新規開始用の第2版は4問、既存記録の第1版は2問を維持します。教材は自作で、公式試験問題ではありません。
- 教材を読む→選択式確認問題に回答→サーバー採点・解説→復習→修了確認→進捗表示。
- ブラウザーで32バイトのランダムな学習キーを生成し、IndexedDBへ保存・読み戻し確認。次回は自動再開。
- 任意のLS1コード表示・書き出し・復旧。URLにキーを入れず、外部QRサービスも使用しません。
- 学習のない記録の30日期限と、初回回答による期限状態の変更。GETでは期限を延長しません。
- 同一リクエストの再送を24時間冪等化。SQLiteの書き込みトランザクションで回答連番を保護。

## 個人情報とローカルデータ

プレビューの開発サーバー全体について、公開環境での「識別情報がどこにも保存されない」検証は未完了です。リバースプロキシ、OS、障害ダンプ、DB、バックアップまで含む正式運用の確認が必要です。

## 一時端末モード 2026年11月8日

ヘッダーの「教室・共用PCで一時利用」を選ぶか、http://127.0.0.1:5173/#temporary を直接開きます。このURLはモードだけを示し、学習キーを含みません。リロード後も一時モードを維持します。既存の個人用IndexedDBを読み込まず、キー・バックアップ状態をIndexedDB、localStorage、sessionStorageへ保存しません。個人モードの保存内容も変更しません。

紙などに控えたLS1コードから同じサーバー記録を再開できます。新規コースの開始も可能ですが、控えがないキーを失うと再開できません。一時モードではコードのファイル書出し・キー更新を表示せず、通常の個人モードでは既存の機能を維持します。

「離席・終了する」で通信を中止し、画面を破棄して一時モードの入口へ戻ります。すでにサーバーへ到達した回答の取り消しではありません。同一サイト・ブラウザーの他の一時モードタブにも終了を通知します。BroadcastChannel非対応・禁止時には他タブの即時終了を保証できないため、利用者交代時には開いたタブをすべて閉じてください。通常保存タブへの終了通知は送りません。

このページでのキー入力・ポインター操作・入力・スクロールを活動とし、60分操作がなければ一時キーを破棄します。IDE作業は活動に含めません。休止・バックグラウンドでタイマーが遅れた場合は、復帰・次操作・API要求・応答の処理時にも期限を判定し、期限後の操作で延命しません。リロード・タブ終了・ページ移動でも一時キーは引き継ぎません。戻る操作でのページ復元時にも再読込みします。サーバーの学習記録自体は削除しません。

一時モードはブラウザープロファイルの初期化機能ではありません。以前に通常モードで保存した他人のキーを掃除するものではなく、OS・ブラウザーの障害ダンプやセッション復元を含む無記録の保証でもありません。教室実導入では専用プロファイル初期化と利用者交代試験が別途必要です。LAN/HTTPS構成の追加は行っておらず、今も同一PCの127.0.0.1上での検証環境です。

## サーバーの学習記録削除 2026年11月8日

個人モードのバックアップ画面に「サーバーの学習記録を削除する」を追加しました。「この端末の記憶を解除」とは別の操作です。削除対象と全端末への影響を確認し、確認チェックを入れてから実行します。一時端末モードにはこの操作を表示しません。削除は現在の所有キーに結び付くサーバー記録・回答・進捗・資格・再送キャッシュに適用し、他の受講者の記録や教材には適用しません。成功時はこのブラウザーの保存キーと表示を解除します。端末の消去に失敗した場合は、サーバー削除は成功したこととサイトデータの手動消去が必要なことを区別して案内します。

POST /api/v1/records/me/delete を追加しました。所有キー、Idempotency-Key、confirm=true、現在のrevisionが必要です。所有者と版をSQLite書込みTX内で再確認します。成功は本文なし204です。削除済みキーの再送は認可を通さず401で、削除結果のキャッシュや資格秘密は残しません。応答喪失時の401だけでは削除成功を断定せず、画面にも結果不明を表示します。

削除台帳は学習DBとは別ファイルの .local/learning.db.deletions へ先にコミットします。内容は記録IDと保持期限で、学習キー・回答内容・氏名は入れません。最短35日を記録しますが、自動台帳削除は未実装で、バックアップへの適用確認なしに台帳を消しません。台帳保存に失敗した場合は学習データを削除しません。台帳保存後に処理が中断した場合は、残ったデータへの認可を拒否し、次回起動時に消去を完了します。

### 更新とバックアップ復元

バックエンド再起動で既存DBにapp_metadata表を追加し、削除台帳を初期作成します。DBを初期化する必要はありません。初期化後は学習DBと台帳の識別子を照合し、台帳の欠落・取り違えでは起動を拒否します。

台帳は学習DBの古いバックアップで上書きしないでください。停止中に learning.db だけを復元し、同じ環境の最新 learning.db.deletions と正しい pepper.bin を維持してから、新しいバックエンドを起動します。起動時に台帳を再適用して、削除済みデータと資格・キャッシュを消去してからAPIを提供します。台帳を別途最新状態でバックアップする運用が必要です。

台帳が同じ識別子の古いコピーかどうかの自動判定は実装していません。台帳導入前のDBバックアップには識別子がないため、最新台帳なしで復元・再初期化してはいけません。台帳を持たない旧アプリへ戻す手順も提供しません。これはローカルSQLite試作向けの実装で、正式PostgreSQL移行、外部への台帳保全、バックアップ全体の運用試験、日次期限削除、24か月保持は引き続き未完了です。SQLiteファイルの未使用領域や古いバックアップを物理上書きする機能ではありません。

## 保存期限の判定と整理 2026年11月8日

未学習記録はempty_expires_onのJST当日から、学習記録はlast_active_monthに24か月を加えた月の1日から利用停止（410）します。たとえば最終活動月2024-11-01の記録は2026-11-01から期限切れです。閲覧・GET・再送だけでは保持期限を延長しません。最初の有効回答で学習記録に切り替え、回答と初回の単元修了確認では最終活動月を更新します。キー更新だけでは延長しません。

期限の整理は新しいローカル開発用コマンド backend/retention.py で行います。これは正式管理コンテナーのlearnctlや二者承認の実装ではなく、LEARNING_ENV=developmentだけで利用する試作です。公開HTTPから呼べる管理エンドポイントは追加していません。

backendディレクトリーで、まず件数を確認します（DB・台帳の新規作成、移行、削除、起動時再適用を行わないプレビューです）。

```powershell
../.venv/Scripts/python.exe retention.py
```

対象を確認して消去する場合は明示指定します。

```powershell
../.venv/Scripts/python.exe retention.py --apply
```

標準出力はmodeとexpired_empty、expired_learning、pending_deletions、deletedの件数だけです。失敗は固定RETENTION_FAILEDと終了コード1で、秘密・パス・SQL詳細を出しません。--databaseで初期化済みの別DBを指定できます。そのDBに対応する最新の .deletions ファイルが必要で、存在しないDBや台帳を新規作成して継続しません。

プレビューは確認時点の参考値で、apply時には各recordの書込みロック取得後に期限・実際の回答・修了根拠を再確認します。期限が過ぎた空フラグだけを信用して学習済み記録を空記録として消去しません。台帳を独立コミットしてから従属を削除し、前回中断した台帳記録も処理します。途中の失敗前に別recordの削除が完了している場合はあります。再実行で再確認・残りの処理を行い、無効な日付は推測して削除せず失敗させます。

日次03:00 JSTの自動起動はまだ登録していません。期限判定による利用停止はAPIで行いますが、実データの消去には上記applyの実行が必要です。WindowsタスクスケジューラやUbuntuの定期ジョブの登録、正式な管理権限・承認・監視・失敗通知は別途実装します。現段階で自動実行が設定済みとは扱わないでください。

## 暗号化復旧ファイル 2026年11月8日

個人端末のバックアップ画面に、パスワード付き復旧ファイルの保存を追加しました。「学習記録を復旧する」画面から保存済みファイルを取り込めます。一時端末モードにはファイルの作成・取込みを表示しません。

この機能は技術仕様の正規化済みHTTPSオリジンに結び付ける規則を維持しています。現在の http://127.0.0.1:5173 ではボタンを無効にして理由を表示します。HTTPだけを例外として受け入れる変更はしていません。HTTPSの検証環境はまだ構築していないため、ブラウザーでの保存・ダウンロード・取込みの一連の実機確認は未完了です。現行のHTTP環境では引き続きLS1コードを利用します。

### 保存と再開の流れ

1. 個人端末で学習を開始し、HTTPSの同じサイトのバックアップ画面から「パスワード付きの暗号化復旧ファイルを保存する」を選びます。
2. 新しいファイル用のパスワードを12文字以上で入力し、同じパスワードをもう一度入力します。パスワードはUTF-8で1024バイトまでです。大文字・小文字・空白を区別し、ファイルとは別に保管します。
3. 暗号化して learning-recovery.json のダウンロードを開始します。書き出し操作は実保存の証明ではないため、保存先にファイルがあることを確認します。
4. 確認や別の個人端末での再開では、同じHTTPSオリジンの「学習記録を復旧する」→「暗号化復旧ファイルを取り込む」を選び、保存したファイルとパスワードを入力します。
5. ブラウザー内で復号・形式確認・資格ID再計算を行い、そのキーでサーバーの学習記録を確認します。学習ホーム・教材・進捗を取得できてから端末へ保存し、状態をrestore_checkedにします。書き出しだけではこの確認状態にしません。パスワードは操作後とダイアログを閉じたときに画面から消えます。

ファイルに含むのは学習キーだけで、学習履歴のオフラインバックアップやGitHub参照は含みません。履歴の本体は引き続きサーバーにあります。キー更新後の旧ファイルや、削除・期限切れの記録には戻れません。パスワードを忘れたファイルを管理者が復号する仕組みはありません。

### 暗号と入力検査

shared/recovery-crypto-spec.md のPBKDF2-HMAC-SHA256 600000回、salt16バイト、AES-256-GCM、IV12バイト、tag128ビットを使用します。取込みは600000〜2000000回だけを受理し、ファイル最大16384バイト、Base64の正準形式・復号長、許可フィールド、アプリ識別子、版、暗号定数、AADのLF連結、復号後のowner資格構造・ID再計算を検査します。saltとIVは書き出しごとに乱数で生成します。

パスワード、復旧ファイル本体、復号JSONをAPIへ送信しません。復号後は既存のAuthorizationで所有キーの有効性を確認します。ファイル処理の入力や例外詳細を画面・ログへ反映しません。JavaScriptの文字列やOS・ブラウザーのメモリーまでの物理消去を保証するものではありません。

## 複数選択と並べ替え 2026年11月8日

単一選択に加えて、Question.kind=multi（複数選択）とorder（並べ替え）に対応しました。複数選択はチェックボックスで正しいものをすべて選びます。選択した順番は採点に影響せず、過不足があれば不正解です。並べ替えは各手順の「上へ」「下へ」で実行順に並べます。マウスのドラッグは不要で、キーボードでもボタンを操作できます。並べ替えはすべての項目の順序が一致した場合に正解です。

APIのchoice_idsは従来どおりUUID配列です。単一選択は1件、複数選択は1〜選択肢数、並べ替えは全項目を1回ずつ要求します。空配列・重複・別問題の選択肢・不正形式・並べ替えの欠落は400で保存しません。正答や解説は問題取得の公開データに含めず、採点結果から返します。多選で順序だけを変えた要求は別の有効回答として採点できますが、同一Idempotency-Keyで本文配列の順序を変えた場合は従来の厳密な要求照合で409になります。

### 既存の学習記録との互換性

既存のcourse_version_id・unit_version_id・question_version_idは変更していません。旧版に問題を足して修了条件を変えず、旧版の2問と進捗・修了・LS1コードによる再開を維持します。新規開始画面には3コースの第2版を表示し、各4問（単一2・複数1・並べ替え1）とします。サーバーのカタログには旧版もavailable=falseで残すため、既存記録の表示は可能です。プレビューAPIは旧版IDを明示した従来の開始要求も受け付けますが、新規選択画面からは旧版を選びません。

旧版の記録を第2版へ自動移行する機能はありません。1記録1コースの試作制限も維持します。新版を試すために既存記録を削除する必要はなく、別のブラウザープロファイルで新規のテスト記録を作成してください。教材本文と学習目標は入門の同じ範囲で、新形式の問題はその制御構造を確かめる自作問題です。正式なDB教材管理や目標別評価・資格全範囲の実装ではありません。
